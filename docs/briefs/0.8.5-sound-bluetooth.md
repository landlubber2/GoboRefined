# Brief: 0.8.5 — laptop sound profile, Bluetooth visibility, Bluetooth sound

Read `docs/briefs/COMMON.md` first and follow it. This is a **release** (`VERSION=0.8.5`). Build environment:
snapshot `repo-build-proof-2`; update test starts from `iso-0.8.4-updated-efi`. (Some older snapshots were
deleted by the owner on 2026-11-16; these two exist.)

## What the owner found on the laptop with 0.8.4 (ThinkPad P15s Gen 2i, Intel Tiger Lake, Intel AX210)

Sound — the firmware fix worked: the card `sof-hda-dsp` exists (`aplay -l` lists HDA Analog and HDMI
devices; the kernel log is clean). But PulseAudio 13 keeps the card switched off and only "Dummy Output" is
offered. `pactl list cards`:

```
Profiles:
    HiFi: Play HiFi quality Music (sinks: 4, sources: 2, priority: 8000, available: no)
    off: Off (sinks: 0, sources: 0, priority: 0, available: yes)
Active Profile: off
Ports: [Out] Speaker (no availability), [Out] Headphones1 (not available), [Out] HDMI1-3 (not available),
       [In] Headphones2 mic (not available), [In] Mic: Digital Microphone (not available)
```

`pactl set-card-profile 0 HiFi` made the speakers work at once ("worked like a wonder"). The owner asks:
"it would be good to leave a menu for users since we won't know every name in the future."

Bluetooth — the adapter, the host name and the pairing agent all work. Pairing from the phone failed only
because the adapter was not discoverable; after `bluetoothctl discoverable on` pairing succeeded. The owner:
"we should bring the discoverability switch back, but for some reason I still couldn't connect to a
speaker." The speaker cannot connect because the system has no Bluetooth audio (PulseAudio 13 was built
without its Bluetooth modules) — that is item 3.

## Items, in priority order

1. **Sound card left "off".**
   a. Automatic: a small session program (started with the desktop, and re-run when a sound card appears)
      that, for every PulseAudio card whose active profile is `off`, selects the best other profile —
      highest priority first, regardless of the "available" flag when no profile is marked available — and
      then makes its sink the default if the default is the null sink (`auto_null`). It must respect a
      choice the user made: if the user set a card to "off" or chose a profile in our menu (item b), do not
      override it (remember the choice per card in a file under `~/.config/goborefined/`). No effect on
      machines where sound already works (the desktop PC with a plain HDA card; the VM).
   b. The menu the owner asked for — Settings → Sound gets real content instead of only a button:
      output device (list of sinks, the default one marked, click to switch), input device, and per sound
      card a "Mode" chooser listing all its profiles by their descriptions (with "(not detected)" for
      unavailable ones, still selectable), plus the existing button that opens the full sound control.
      Changes apply at once and persist (PulseAudio's own restore modules or our file).
   c. Find out why PulseAudio 13 marks the HiFi profile unavailable (all input ports unavailable? UCM
      1.2.2 jack definitions?) only as far as 20 minutes of reading goes; write the finding into
      `HANDOFF.md`. Do not rebuild PulseAudio for this.
   d. Test in the VM by simulation: a null card cannot have profiles, so test the selection logic against
      captured `pactl list cards` output (use the block above as a fixture; add fixtures for a normal HDA
      card and for "user chose off") and run the program against the VM's real card to prove it changes
      nothing there.
2. **Bluetooth visibility.** Settings → Bluetooth: a switch "Visible to other devices" (discoverable), and
   the adapter is made discoverable automatically while that page is open and for 3 minutes after "Search
   for devices" (BlueZ `DiscoverableTimeout`), then off again; the taskbar Bluetooth menu gets the same
   switch. Pairing started from a phone must then reach our agent dialog (test with the two virtual
   controllers as in the 0.8.4 notes: the peer finds this one only while it is discoverable).
3. **Bluetooth sound (speakers and headphones).** This is the task of the former `0.9.2` brief, folded in:
   - first 30 minutes reading, no building: which PulseAudio is on the image and how it was configured;
     is the SBC codec library there; BlueZ is 5.54;
   - preferred route: build the missing `module-bluez5-*`, `module-bluetooth-*` and `libbluez5-util` for
     the **same** PulseAudio version (autotools, `--enable-bluez5`, needs `sbc`) and install only those
     files next to the existing modules, or the whole PulseAudio rebuilt at the same version if that is
     simpler and equally safe; fallback BlueALSA; **no PipeWire**;
   - load `module-bluetooth-policy` and `module-bluetooth-discover` in every session; a connected audio
     device becomes the default output and sound falls back to the speakers when it disconnects (item 1's
     program must not fight this);
   - Settings → Bluetooth: Connect on an audio device connects A2DP; remove the "no sound" warning when the
     modules are present; show "Connected — playing sound here"; when connecting fails show BlueZ's reason
     in plain words;
   - A2DP playback is the goal; headset microphone only if it works without extra daemons, otherwise say
     it is not supported;
   - VM: no Bluetooth hardware. Check that the modules load, wired sound still works, login is not slower;
     with the `btvirt` emulator from the 0.8.4 lab notes try whether an A2DP endpoint registers. Say
     plainly that the laptop is the test.
   Time box: 2 hours. If it does not come together, ship items 1 and 2 as 0.8.5 without it and report
   exactly where it stopped.
4. Only if cheap: the taskbar volume icon's menu lists the output devices to switch between (speakers /
   headphones / HDMI / Bluetooth).

## What to tell the owner to check on the laptop (put it into `dist/README.md`)

Sound plays after login without any command; headphones plugged in take over and speakers return when
unplugged; the microphone records; Settings → Sound shows the devices and the mode chooser; the phone finds
the laptop from Settings → Bluetooth and pairs with the number dialog; the speaker connects and plays.
If Bluetooth sound fails: `pactl list short modules | grep -i blue`, `pactl list short sinks`,
`bluetoothctl info <address>`, and `gobo-report`.

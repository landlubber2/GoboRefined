# Brief: 0.9.5 — programs for daily work

Read `docs/briefs/COMMON.md` first and follow it. This is a **release** (`VERSION=0.9.5`).

## What the owner asked for (translated from Polish, over several messages)

"Please add KolourPaint and VS Code and conda-mini so you can run something in VS Code." Later: "Visual
Studio (you mentioned there is something similar), Anaconda Prompt, something simple for jpg, mp4…"

## Before starting (the launching session checks these with the owner)

Defaults are used unless the owner answered otherwise under "Answers from the owner".

1. Code editor: **VSCodium** (the open-source build of VS Code, same editor, no Microsoft telemetry or
   licence terms; its extension shop is Open VSX, which lacks a few Microsoft-only extensions) — default.
   Alternative: Microsoft's own VS Code build (proprietary licence; all extensions). The owner chooses.
2. Paint program: KolourPaint needs dozens of KDE libraries built first. Default: **a lighter paint program**
   that builds here (see item 4); KolourPaint only if the owner insists and accepts a large, slow build.
3. Conda: **Miniforge** (community installer, conda-forge packages, no licence restrictions) — default.
   Alternative: Anaconda's Miniconda (free for personal use, its terms restrict organisations).

## First: take stock (30 minutes, no building)

List what the image already has for: picture viewing, picture editing, video and audio playback (is
`ffmpeg`/`mplayer`/`mpv`/`vlc` there? which codecs?), archives (zip/7z/rar tools and a graphical archive
manager), PDF viewing, calculator, task manager, text editor (L3afpad was added in 0.8.1). Write the table
into `HANDOFF.md`. Check free space: every program lands in the read-only system slot (about 6 GB free in a
16 GiB slot, 3 GB in a 12 GiB one, minus what 0.8.4 and 0.9.1 added). Keep the total added by this release
under **1.5 GB installed**; if the wish list does not fit, apply the priority order below and say what was
left out.

## Programs, in priority order

Every program: under `/Programs/<Name>/<Version>`, built or unpacked by a new step in
`spin/build-programs.sh`, source pinned in `build/sources.manifest`, licence in `docs/third-party.md`, a
proper menu entry and icon (Papirus has icons for most — check the `.desktop` `Icon=` name resolves), file
associations in `look/gobo11/xdg/mimeapps.list`, light and dark both readable, starts in the VM.

1. **Code editor (VSCodium or VS Code, see question 1).** Official x86_64 tarball (Electron; needs glibc
   2.28+: fine; handle it like ONLYOFFICE was handled — read that step). Check: starts under Awesome
   without a compositor problem, window decorations (use the system title bar setting), opens a folder,
   integrated terminal works with the shell of the user, file dialogs open in the home folder. It writes
   its settings in the home folder: nothing in the slot may need write access. Menu entry "Code".
2. **Conda prompt.** Ship the Miniforge installer (or the alternative) inside the image, **not** a
   pre-installed tree: the first start of the menu entry "Conda Prompt" installs it into `~/miniforge3`
   (per user, in the home folder, survives system updates, no root), then opens a terminal with the base
   environment active; later starts open the terminal directly. Do not touch the shell start-up files of
   the user unless they choose "activate conda in every terminal" in the first-run dialog. Verify in the
   VM (needs network): first run installs, `conda create -n test python` works, `python -c "print(1)"`
   runs. Make the code editor find it: document in `dist/README.md` how to pick the interpreter; if the
   editor has a setting for the default Python path that can be pre-seeded per user without overwriting
   their settings, do it.
3. **Picture viewer** for jpg/png/webp/gif: prefer one from the same family as the file manager that
   builds with autotools and GTK 3 (GPicView with `--enable-gtk3`, or similar). Default program for
   images; arrow keys go to the next picture in the folder; rotate, zoom, delete-to-trash.
4. **Simple paint / picture editing** (crop, resize, draw, text, save as jpg/png): a GTK 3 program that
   builds without meson (candidates: mtPaint 3.50 built for GTK 3; check others before choosing; Pinta
   needs Mono, Drawing needs meson, GIMP 2.10 needs GTK 2 — all out). "Edit" in the context menu of the
   file manager for images opens it. If nothing suitable builds within an hour, report the candidates and
   their blockers instead of forcing one.
5. **Video and audio player** for mp4/mkv/webm/mp3: if `mpv` or `vlc` can be built here within 90 minutes
   (mpv up to 0.35 builds with waf and needs ffmpeg; VLC 3 builds with autotools and Qt 5; either needs an
   ffmpeg — check whether the image has one and how old), add it with a simple interface (for mpv: its
   on-screen controller plus a `.desktop` entry; default for video and audio files). Mind patents and
   licences only as facts in `docs/third-party.md` (ffmpeg LGPL/GPL build options). Hardware-accelerated
   decoding is a bonus, not a requirement. Test with small sample files generated in the VM (ffmpeg
   `testsrc`), not downloaded films.
6. **Small utilities, each only if it builds in under 20 minutes** (LXDE family, GTK 3, autotools):
   archive manager (Xarchiver or similar: open and create zip, 7z, tar; "Extract here" in the file
   manager), calculator (Galculator), task manager (LXTask: "what is using my CPU and memory", ending a
   program). Add a "Task manager" entry to Settings → About or the power menu area if there is room.
7. If the owner chose KolourPaint in question 2: only after everything above, in the remaining budget;
   stop when the dependency chain (KDE Frameworks for Qt 5.14, extra-cmake-modules) passes two hours of
   building, and report how far it got.

## Integration

- The Simple account kind from 0.9.1 (if released): decide for each new program whether it is on the default
  allowed list (viewer, player, calculator: yes; code editor, conda prompt, task manager: no).
- App search finds every new program by obvious words ("code", "python", "conda", "video", "paint",
  "zip"). The dots menu puts them into sensible categories.
- `apply.sh` must add the new default associations for existing users without overwriting choices they
  made (it already does this for text files — follow that code).

## Tests

For each program: starts from the menu and from a file double-click, the window gets a title bar and focus
(`vm/input-test.sh` stays green), closes cleanly, and survives the update test (programs arrive through the
update; settings of the user stay in the home folder). Screenshots `docs/screenshots/0.9.5-*.png`.

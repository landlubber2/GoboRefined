# Brief: 0.9.2 — Bluetooth speakers and headphones play sound

Read `docs/briefs/COMMON.md` first and follow it. This is a **release** (`VERSION=0.9.2`), but a small one.

## Before starting

Only start after the owner confirmed on the laptop that 0.8.4's Bluetooth pairing works (phone and speaker
pair and connect). If pairing still fails, that is a different task: ask for `gobo-report` output and fix
pairing first.

## Why

PulseAudio 13 on the image was built without its Bluetooth modules, so a paired speaker never becomes a
sound output. The Settings → Bluetooth page says so. The owner tried to use a Bluetooth speaker.

## Items

1. **Find the cheapest working route** (30 minutes of reading, no building): which PulseAudio is on the
   image and how it was built (recipe, configure options); is the SBC codec library there; BlueZ is 5.54.
   Options, in order of preference:
   a. rebuild the same PulseAudio version with `--enable-bluez5` (needs `sbc`; PulseAudio 13 builds with
      autotools) as `/Programs/PulseAudio/<same version>-r2` or by adding only the built
      `module-bluez5-*`/`module-bluetooth-*` files and `libbluez5-util.so` next to the existing modules —
      the smallest change, lowest risk;
   b. only if (a) is impossible: `bluez-alsa` (BlueALSA, autotools) plus a PulseAudio ALSA sink — more
      moving parts.
   Do not replace PulseAudio with PipeWire in this task (meson, and a much larger change).
2. Build it, pin sources in the manifest, load the modules for every session
   (`module-bluetooth-policy`, `module-bluetooth-discover`), and make a connected audio device the default
   output automatically, falling back to the speakers when it disconnects.
3. Settings → Bluetooth: remove the "no sound" warning when the modules are present; for audio devices show
   "Connected — playing sound here" and a button to switch back to the speakers. The volume icon and the
   sound control (PaVuControl) must list the device.
4. Profiles: A2DP (music) is the goal. Headset microphone (HSP/HFP) only if it works without extra daemons;
   otherwise state clearly that Bluetooth microphones are not supported.
5. VM test: there is no Bluetooth hardware. Use BlueZ's emulator (`btvirt` with two virtual controllers) if
   it is on the image or cheap to build from the BlueZ source already pinned, to check that the modules
   load and a virtual A2DP endpoint appears; otherwise verify module loading and absence of regressions
   (wired sound in the VM still works, PaVuControl starts, login is not slowed down) and say plainly that
   the laptop is the test. Give the owner exact steps and the commands to run if it fails
   (`pactl list short modules | grep blue`, `pactl list short sinks`, `gobo-report`).

## Delivery

As in COMMON.md ("Release delivery"). In `dist/README.md`: how to play sound on a Bluetooth speaker (pair in
Settings → Bluetooth, connect, sound moves by itself), and what is not supported.
